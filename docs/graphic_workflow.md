# 每日图文内容生产流程

本流程用于把每日内容大纲转成一套可继续交给 AI / 设计工具执行的图文内容生产包，覆盖分页脚本、图片生成 prompt、发布文案、检查清单和复盘字段。

## 1. 填写每日大纲

在 `input/graphic_outline_template.md` 中填写：

- 主题名称
- 目标读者
- 核心观点
- 主要知识点
- 页数建议
- 视觉风格方向
- 希望强调的案例、公式、方法论或框架
- 是否需要互动引导
- 是否需要延续上一期风格

如果信息不完整，后续生成时可基于「设计策略 / 产品经理 / 用户研究 / 运营干货」定位补全合理结构，但不能虚构具体数据。

## 2. 生成图文内容包

运行：

```bash
python scripts/generate_graphic_content_package.py --date 2026-05-29 --slug demand-priority
```

脚本会在 `output/YYYY-MM-DD_slug/` 下生成：

- `graphic_content_package.md`

该文件是一份结构化执行 prompt，要求输出：

1. 分页图文脚本
2. 每页图片生成 prompt
3. 每页排版说明
4. 小红书发布标题
5. 小红书正文文案
6. 抖音图文发布文案
7. 标签建议
8. 文件命名规则
9. 发布前检查清单
10. 数据复盘字段
11. 下一次内容优化建议

## 3. 默认页数结构

默认生成 7–9 页图文，除非大纲明确要求其他页数。

推荐 9 页结构：

1. 封面页
2. 概念解释 / 问题引入
3. 分类框架 / 核心模型
4. 方法步骤 / 判断标准
5. 工具框架 1
6. 工具框架 2
7. 案例转化 / 应用路径
8. 总结页 / 模板页
9. 互动页 / 评论引导页

内容较短时可压缩为 7 页：封面、定义、分类、方法、案例、总结、互动。

## 4. 每页内容规范

每页必须包含：

- `page_number`
- `page_title`
- `page_goal`
- `layout_type`
- `exact_text`
- `visual_elements`
- `image_prompt`
- `design_notes`

文字要求：

- 单页只讲一个核心信息。
- 标题短、强、明确。
- 正文不超过 3–5 个信息块。
- 每个信息块尽量控制在 1–2 行。
- 避免大段文字堆叠。
- 适合手机端阅读。
- 信息有递进，不重复。
- 保留可直接上图的精炼表达。

## 5. 视觉风格规范

默认采用「蓝色严谨专业风」：

- 主色：深海军蓝 / 深灰蓝，用于主标题、关键文字。
- 高亮：科技蓝，用于重点词、按钮、标签、图标。
- 背景：冷白、浅蓝灰、深灰蓝渐变。
- 辅助：浅灰蓝，用于边框、辅助线、网格。
- 暖色限制：橙色 / 珊瑚橙只用于互动区、风险提醒、关键警示。

背景可使用深灰蓝渐变、冷白到浅蓝灰渐变、微弱网格线、半透明几何纹理、点阵纹理、科技感路径线、细线框架图形、轻量坐标轴或四象限装饰。背景不能抢正文。

## 6. 常用页面版式

| 版式 | 适合内容 | 核心要求 |
| --- | --- | --- |
| 封面页 | 方法论、工具类、系列开篇 | 深灰蓝渐变、巨型标题、中心模型、价值标签、品牌标识 |
| 左右分栏页 | 分类 + 步骤、对比 + 操作 | 两栏宽度稳定、卡片纵向对齐、细线或留白分隔 |
| 表格页 | 分类说明、评分标准、维度拆解 | 深蓝表头、细边框、统一行高、重点词克制突出 |
| 公式页 | ICE、RICE、评分模型 | 公式成为视觉中心，上方解释维度，下方一句解释 |
| 流程页 | 从问题到方案、从洞察到策略 | 节点卡片化、箭头统一、节点不过多 |
| 总结互动页 | 最后一页、评论引导 | 上半总结、下半 CTA，暖色只用于互动区 |

## 7. 发布前检查

- 分页是否有清晰递进。
- 每页是否只有一个核心信息。
- 图片 prompt 是否包含主题、比例、风格、配色、排版、文字、图标、品牌、页码、禁止事项。
- 标题是否像一个判断，而不是泛泛的知识点。
- 是否避免虚构数据和未经验证的绝对化结论。
- 小红书与抖音图文文案是否分别适配平台语气。
- 是否设置评论引导和保存理由。

## 8. 数据复盘

发布后记录：

- 曝光量
- 点击率 / 封面进入率
- 完读率
- 收藏量
- 评论量
- 转发量
- 涨粉量
- 评论关键词
- 高互动页码
- 下一次优化动作
